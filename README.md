# Делком — учебный практикум

Простой сайт на **HTML + CSS + JavaScript**. Без React, npm, сборки, сервера и внешних библиотек.

## Быстрый запуск

1. Распакуйте весь архив в одну папку.
2. Откройте `index.html` в браузере.
3. Выберите вариант и режим.

Не открывайте HTML прямо внутри ZIP: сначала распакуйте папку. Все файлы должны оставаться рядом в исходной структуре. Для устойчивого сохранения прогресса удобно использовать GitHub Pages или локальный сервер: некоторые браузеры ограничивают localStorage у файлов `file://`.

## Структура файлов

| Файл | Назначение |
|---|---|
| `index.html` | Каркас: шапка, область страниц, подключение CSS и JS |
| `styles.css` | Цвета, размеры, карточки, адаптация под экран |
| `app.js` | Навигация, ответы, таймер, сохранение, результат |
| `data/source-tests.js` | Вопросы из DOCX и восстановленные ключи |
| `data/author-tests.js` | Авторские вопросы, сгруппированные полем `topic` |
| `data/lecture-tests.js` | Тесты со скриншотов — сюда добавлять полные варианты |
| `data/past-year.js` | Прошлогодние варианты — сюда добавлять полные варианты |
| `data/tests.js` | Собирает каталог из файлов с вопросами |
| `README.md` | Эта инструкция |
| `CONTENT_NOTES.md` | Источники, оговорки и замечания к ключам |
| `.nojekyll` | Позволяет публиковать файлы как обычный статический сайт |

### Почему один HTML

Вкладки переключаются по части адреса после `#`: например, `#section/author` или `#test/author-1`. Функция `render()` в `app.js` выбирает, что показать внутри `<main>`.

Для такого тренажёра один каркас удобен: шапка и логика теста не копируются в несколько HTML-файлов. Разделение всё равно есть — оформление, логика и вопросы лежат отдельно. Если захочется настоящих отдельных страниц, можно позже вынести каталог в несколько HTML и оставить общий движок теста.

## Как изменить вопрос

Откройте нужный файл в папке `data` в текстовом редакторе. Каждый вопрос — обычный объект JavaScript:

```js
{
  id: "my-question-1",
  topic: "Переговоры",
  text: "Что означает BATNA?",
  type: "single",
  options: [
    "Наилучшая альтернатива соглашению",
    "Первая предложенная цена",
    "Обязательная уступка"
  ],
  answer: [0],
  explanation: "BATNA показывает, что сторона может сделать, если соглашения не будет.",
  source: "Лекция 07–08, с. 11, 14.",
  status: "Авторский вопрос",
  note: ""
}
```

- `id` — уникальный постоянный код вопроса. Не используйте один код для разных вопросов.
- `text` — формулировка; `\n` добавляет перенос строки.
- `type: "single"` — один ответ; `type: "multiple"` — несколько возможных ответов.
- `options` — варианты в том порядке, в котором они показываются.
- `answer` — **индексы с нуля**. `[0]` — первый; `[1, 3]` — второй и четвёртый. При перестановке вариантов измените индексы.
- `explanation` — разбор; `source` — источник и страница; `note` — оговорка, если нужна.
- `status` — например, «Официальный ключ» только при наличии проверенного ключа, иначе «Восстановленный ключ».
- Ставьте запятую между соседними объектами. Сохраняйте обычные прямые кавычки `"`, а не типографские кавычки редактора.

Добавьте объект в конец массива `SOURCE_QUESTIONS` — каталог автоматически разобьёт вопросы на части по 21. Для `AUTHOR_QUESTIONS` вопросы объединяются по одинаковому `topic`; новый `topic` создаст новую карточку. Пробник берёт первые пять вопросов каждой темы, всего не более 40.

Если вы существенно изменяете банк, обновите описания и счётчики в `app.js`/`data/tests.js`. Если меняете смысл вопроса, дайте ему новый `id`, чтобы сохранённый старый ответ не был принят за ответ на новый вопрос. Для полного сброса сохранений после крупной переработки измените `storageKey` в `app.js`, например на `delcom-v2`.

## Как добавить вариант «Тесты с лекций»

Замените пустой массив в `data/lecture-tests.js` следующим кодом, затем заполните своими вопросами:

```js
window.LECTURE_TESTS = [
  {
    id: "lecture-01",
    category: "lecture",
    title: "Тест с лекции 1",
    minutes: 10,
    description: "Вопросы со скриншотов первой лекции.",
    questions: [
      {
        id: "lecture-01-q01",
        topic: "Основы коммуникации",
        text: "Здесь точная формулировка вопроса",
        type: "single",
        options: ["Первый ответ", "Второй ответ", "Третий ответ"],
        answer: [1],
        explanation: "Здесь объяснение правильного ответа",
        source: "Скриншот 1, вопрос 1",
        status: "Восстановленный ключ",
        note: ""
      }
    ]
  }
];
```

Для второго варианта добавьте ещё один объект после первого через запятую. Не создавайте вторую строку `window.LECTURE_TESTS = ...`, иначе она перезапишет первый массив.

Для прошлого года схема та же, но файл — `data/past-year.js`, имя массива — `window.PAST_YEAR_TESTS`, категория — `"past"`, код варианта, например, `"past-2025-1"`.

## Как поменять время и внешний вид

- `minutes` в объекте теста — длительность экзамена. В `data/tests.js` сейчас 25 минут для каждой части сборника, 10 для тематических вариантов и 40 для общего пробника.
- В тренировке `minutes` не используется.
- Основные цвета находятся в начале `styles.css`, в блоке `:root`.
- Тексты страниц находятся в функциях `catalog`, `detail`, `guide` внутри `app.js`.

## Как выложить на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Загрузите **содержимое распакованной папки**: `index.html` должен лежать в корне репозитория, рядом с `app.js`, `styles.css` и папкой `data`. Не загружайте только ZIP.
3. Откройте настройки репозитория: **Settings → Pages**.
4. В **Build and deployment → Source** выберите **Deploy from a branch**.
5. Укажите ветку с файлами, обычно `main`, и папку **/(root)**. Нажмите **Save**.
6. Дождитесь публикации; GitHub покажет адрес сайта в разделе Pages.

Ссылки к файлам относительные, поэтому сайт работает и внутри пути репозитория. Роуты после `#` не требуют настройки перенаправлений.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Что проверить после своих изменений

1. Откройте главную, убедитесь, что появилась карточка.
2. Начните тренировку, выберите ответ: до нажатия «Готово» проверки быть не должно. Нажмите «Готово»: ошибочное задание и его номер становятся красными, ответ блокируется.
3. Для multiple проверьте неполный набор, точный набор и набор с лишним вариантом.
4. Перезагрузите страницу: текущий вопрос и выбор должны сохраниться.
5. Повторите проверку кнопки «Готово» и блокировки в экзамене. Убедитесь, что блокировка сохраняется после перехода между вопросами и перезагрузки.
6. Завершите попытку, откройте разбор и работу над ошибками.

Если сайт перестал открываться после изменения JS, проверьте запятые, кавычки и скобки; ошибка будет показана в консоли разработчика браузера. Для синтаксической проверки при установленном Node.js можно использовать `node --check app.js` или `node --check data/lecture-tests.js`.

## Ограничения

- Это тренажёр для самоподготовки, не защищённая экзаменационная система: ключи лежат в JavaScript и доступны в исходниках.
- Один активный тест на браузер. Не проходите две попытки одновременно в разных вкладках: они используют общее сохранение.
- Нет аккаунтов, сервера, аналитики или синхронизации между устройствами. Сайт не отправляет ответы в сеть.
- Экзаменационный таймер использует часы устройства; это не средство защиты от изменения времени.
- Очистка данных браузера удаляет прогресс. Для `file://` сохранение зависит от политики браузера.
- Учебная оценка: 1 балл за точный набор, 0 за ошибку или пропуск. Официальные веса сложности не воспроизводятся.
- После переработки ответов прежний лучший результат автоматически не пересчитывается.
